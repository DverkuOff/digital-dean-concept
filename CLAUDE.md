# «Ориентир» — цифровой деканат (концепт для MGIMO×AI CHALLENGE)

Веб-прототип личного кабинета студента по кейсу «Цифровой деканат будущего». Расписание, успеваемость, рейтинг-навигатор «что если», заявки со статусами и очередь методиста, уведомления. Данные вымышлены, это не официальный сервис вуза.

## Где что лежит
- Требования и критерии жюри: `docs/00-brief.md` (выжимка; оригинал кейса — в `brief/`, его не правим).
- План, приоритеты и статус: `docs/plan.md`. Сценарий показа и аккаунты: `pitch/demo-script.md`.
- Спеки: `docs/specs/` — `rating.md`, `access-control.md`, `data-model.md`, `today.md`, `pwa.md`. Меняешь поведение — обнови спеку.
- Журнал решений, ошибок ИИ и находок проверки: `docs/decisions.md`. Постановки задач: `docs/process/prompts.md`.
- Код: правила, карта модулей и проверки перед коммитом — @AGENTS.md. Правила по путям: `.claude/rules/` (security, ui, data).

## Инструменты для ассистента в этом репо
- Хук `.claude/hooks/lint-edited.sh` (PostToolUse на Edit/Write): прогоняет ESLint по изменённому `.ts`/`.tsx` и возвращает ошибки сразу.
- Агент `access-reviewer` (`.claude/agents/`): ревью серверного кода на IDOR, роли и утечки через агрегаты. Запускать перед коммитом фичи, которая читает или пишет данные студента.
- Команды `/screens` (переснять скриншоты на свежем демо) и `/demo-check` (полная проверка перед показом).

## Запуск
`npm run db:up && npm run db:reset && npm run dev` → http://localhost:3100. Тесты: `npm test`, `PW_CHANNEL=chrome npm run test:e2e`.

## Как работаем
- Условия конкурса берём из `docs/00-brief.md`, не из памяти.
- Сначала сквозной путь брифа (войти → расписание и оценки → заявка → статус), потом остальное. «Готово» значит, что тест или ручной проход сценария зелёный, а не «код написан».
- Новая находка безопасности или бага: сначала тест, который падает, потом правка. Тесты на доступ проверяем «на поломку» (временно убрать проверку — тест должен упасть).
- Значимые решения и ошибки ИИ — коротко в `docs/decisions.md`: это материал для описания процесса.
- `main` всегда собирается и проходит тесты. Коммиты маленькие, по-русски, после каждого работающего шага, затем push.
- Коммиты — от имени автора репозитория, без служебных трейлеров соавторства (`Co-Authored-By` и подобных) и ссылок на сессии. Использование ИИ при этом не скрываем: оно подробно описано в `docs/process/` и в README.
- Что не сделано по-настоящему — пометка `MOCK` в коде и README. Сейчас моков нет.
- Без лишних сервисов и зависимостей: каждая новая штука должна работать на демо. После изменения зависимостей — чистая установка (см. AGENTS.md).
- Секреты только в `.env` (его не читаем и не коммитим), имена переменных — в `.env.example`.
