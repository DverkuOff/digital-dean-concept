# Спека: рейтинг-навигатор «что если»

Статус: реализовано 17.11.2026. Код: `src/lib/rating/calc.ts` (чистые функции), `src/lib/rating/config.ts` (правила), `src/app/(student)/rating/*` (экран). Тесты: `src/lib/rating/calc.test.ts`, `e2e/03-rating.spec.ts`.

## Зачем
Для студента МГИМО «как у меня дела» означает «мой рейтинг и что он мне открывает» (docs/research/03-domain.md §2): третий язык, стипендия, кафедра. Сейчас рейтинг виден постфактум. Навигатор отвечает на вопрос заранее: «что будет, если сдам на N».

## Условность правил
Официальное положение о БРС МГИМО прочитать не удалось (сайт закрыт анти-ботом, 03-domain). Поэтому:
- все числа живут в `config.ts`, код расчёта от них не зависит;
- на экране всегда видна пометка «условные правила концепта, вуз настраивает их в конфиге»;
- юнит-тест «другой вуз — другой порог сдачи» доказывает, что правила меняются без правки кода.

## Входные данные
`DisciplineResult[]` — по одной записи на дисциплину студента:

| Поле | Смысл |
|---|---|
| `credits` | ЗЕТ, вес в рейтинге |
| `controlType` | `exam`, `diff_credit` (дают балл) или `credit` (зачёт без балла) |
| `status` | `passed` — закрыта, `debt` — академический долг, `open` — сессия впереди |
| `finalScore` | итоговый балл 0–100; у долга — балл последней попытки; у открытой — `null` |
| `passedOnRetake` | закрыта на пересдаче |

`Hypothesis` — словарь `disciplineId → балл` для режима «что если».

## Формула
```
рейтинг = Σ(балл_i × ЗЕТ_i) / Σ ЗЕТ_i,  по дисциплинам с баллом, округление до 0,1
```

| Случай | Что идёт в рейтинг |
|---|---|
| Закрыта вовремя | итоговый балл |
| Закрыта на пересдаче | min(балл, `retakeMaxScore` = 74) |
| Долг без гипотезы | балл последней попытки (долг тянет вниз) |
| Долг, гипотеза ≥ `passScore` (60) | min(гипотеза, 74), долг считается закрытым |
| Долг, гипотеза < 60 | гипотеза, долг остаётся |
| Открытая без гипотезы | не входит |
| Открытая с гипотезой | гипотеза; если < 60 — появляется долг |
| Зачёт (`credit`) | в рейтинг не входит, незачёт = долг |

Баллы гипотез обрезаются в 0–100.

## Пороги (конфиг, условно)

| id | Порог | Рейтинг от | Без долгов |
|---|---|---|---|
| `scholarship` | Академическая стипендия | 70 | да |
| `third_language` | Третий иностранный язык | 75 | нет |
| `department` | Кафедра мировой экономики (проходной прошлого года) | 82 | да |
| `increased_scholarship` | Повышенная стипендия | 90 | да |

`evaluateThresholds` возвращает для каждого порога `reached`, `gap` (сколько баллов не хватает) и `blockedByDebt`.

## Место на курсе
`placeInCohort(my, others)` = 1 + число однокурсников со строго большим рейтингом; равные делят место.
- Рейтинги однокурсников считает сервер той же функцией (`getCohortRatings` в `src/server/dal/grades.ts`), и **они не покидают сервер**. В браузер уходят точное место «сейчас» и гистограмма: число однокурсников в корзинах по 5 баллов (`summarizeCohort`). В режиме «что если» место оценивается по гистограмме (`estimatePlace`, внутри корзины распределение считается равномерным) и показывается как «≈ N».
- При выборке меньше 10 человек (`MIN_COHORT`) место не показывается: по нему вычисляются чужие оценки.
- Крайние корзины с 1–2 людьми сливаются с соседними, пока в них не наберётся 3 человека (`MIN_EDGE_BUCKET`): лучших и худших на курсе все знают. Цена — у краёв оценка места «что если» неточна до ±2.
- Допущение демо: из агрегата исключены все студенты с аккаунтом (демо-персонажи и их копии). В боевой версии аккаунт есть у всех, и исключать нужно только явный признак демо-персонажа.
- Демо-персонажи и их копии в агрегат не входят.
- В режиме «что если» мой прогноз сравнивается с **текущими** рейтингами однокурсников. Это упрощение концепта: их сессия тоже впереди. Пометка есть в спеке, на экране — «место считается по рейтингам N однокурсников без имён и оценок».

## «Сколько нужно»
`requiredAverageForTarget(results, cfg, target, fixed)` — средний балл по открытым дисциплинам без гипотезы, чтобы прогноз дотянул до `target`. `null` — недостижимо даже на 100, `0` — уже достигнуто.

## Экран
1. Индикатор: число (текущее или прогноз), дельта к текущему, место на курсе и сдвиг мест.
2. Шкала 50–100 с отметками порогов, пунктир — текущее значение, круг — прогноз.
3. Список порогов: пройден / не хватает N / мешает долг; «откроется!» подсвечивает изменение.
4. Режим пересдачи (если есть долг): лестница попыток «Экзамен → Пересдача 1 → Пересдача 2 → Комиссия» из `exam_attempt`, «осталось попыток», ползунок «если пересдам на N» и быстрые кнопки 60/70/74. Кнопки «Записаться на консультацию» и «Подать заявление» создают **обычную заявку** в учебный офис (`quickRetakeRequestAction`): дисциплина проверяется по своим долгам на сервере, повторное нажатие ведёт на уже поданную заявку.
5. «Что если: зимняя сессия»: ползунки по открытым экзаменам и дифзачётам, стоят на среднем по срезам; кнопки «всё на 70/80/90»; подсказка «сдайте в среднем на N+».

Расчёт идёт в браузере той же чистой функцией, что и на сервере: ползунок отвечает мгновенно, без запросов.

## Контрольный пример (сид, Орлов)
34 ЗЕТ с баллом, долг по макроэкономике (5 ЗЕТ, последняя попытка 48):
- сейчас 68,4, стипендия закрыта долгом, не хватает 1,6;
- «пересдам на 70» → 71,7, долг закрыт, стипендия открывается, место на курсе растёт.
Закреплено в `calc.test.ts` и `e2e/03-rating.spec.ts`.
