## Постановка 1. Ведущий разработчик прототипа (17.11)

Сокращённо, по смыслу; полная версия хранится в истории сессии.

> Ты ведущий разработчик веб-прототипа «Цифровой деканат будущего»… Сначала прочитай CLAUDE.md, docs/00-brief.md, critique.md §5–7, 04-tech.md, 03-domain.md, decisions.md.
> **Что выбрано (не пересматривай):** ядро полностью; очередь методиста одной страницей без канбана; центральная фича — рейтинг-навигатор «что если» (100-балльная шкала, пороги с пометкой «условные правила концепта», ползунок «если сдам на N», место на курсе только агрегатом); у второго студента долг → лестница попыток и кнопка, которая создаёт обычную заявку. Формула — чистая функция + конфиг + спека + юнит-тесты.
> **Обязательные требования:** IDOR-защита в слое доступа к данным, Server Actions считаем публичными эндпоинтами, чужая заявка → 404, Playwright-тест на это; argon2id; секреты только в .env; только вымышленные данные; плашка «концепт» на каждой странице; сид относительно now(); 360 px; пустые состояния, ошибки и загрузка.
> **Порядок:** план → каркас и сквозной путь брифа → IDOR-тесты → рейтинг → «Сегодня» и полировка → Dockerfile для Amvera (не деплоить).
> **Git:** маленькие коммиты по-русски, без соавторства ИИ, проверка перед каждым push.

Почему так: решение о составе принято заранее на этапе отбора, поэтому постановка запрещает его пересматривать и тратить время. Требования брифа перечислены как проверяемые условия («→ 404», «Playwright-тест», «360 px»), а не пожелания. Порядок работ задаёт, что урезается последним.

Что вышло:
- docs/plan.md и pitch/demo-script.md — первым коммитом.
- Сквозной путь брифа, очередь методиста, рейтинг-навигатор и «Сегодня» — за один день, все сценарии закрыты Playwright-тестами.
- Спеки docs/specs/{rating,access-control,data-model,today}.md, правила AGENTS.md и .claude/rules/.

## Приёмы, которые сработали

1. **Чистая функция + тест до экрана.** Формулу рейтинга и правила «Сегодня» ИИ писал как функции без БД, с контрольным примером из сида (Орлов 68,4 → 71,7 при пересдаче на 70). Ошибку схлопывания дублей (падежи) нашла самопроверка на строках сида, юнит-тест её закрепил, см. docs/decisions.md.
2. **Сверка с актуальной документацией.** Перед кодом агент читал доки Better Auth 1.7 (context7) и Next.js 16 из `node_modules/next/dist/docs`: в Next 16 middleware называется `proxy.ts`, в новом шаблоне включён `cacheComponents`. Без сверки код был бы под Next 14/15.
3. **Тест безопасности с контрольным опытом.** Проверка «студент вызывает действие методиста» сопровождается отправкой той же формы методистом, иначе зелёный тест мог бы означать сломанный запрос.
4. **Правила для ИИ по путям.** `.claude/rules/security.md` подгружается, когда агент трогает `src/server/**`: «владелец в WHERE, а не проверкой после выборки».

## Ошибки ИИ и как их поймали
Сводка (подробно — docs/decisions.md):

| Ошибка | Чем поймали |
|---|---|
| Поиск названия дисциплины без учёта падежей, дубль карточки | самопроверка на данных сида, закреплено юнит-тестом |

## Постановка 2. Второй заход: зависимости и фичи у аналогов (17.11)

> Сначала Dependabot (minimatch, esbuild): обнови через overrides, проверь build и тесты. Потом фичи по выгоде, каждая отдельным коммитом, после каждой build + unit + e2e (360 px) зелёные: PWA с офлайном для расписания, оценок и «Сегодня» (кэш только для своего пользователя, при выходе очищается); подписка на расписание в календарь по секретному токену с перевыпуском; прозрачность заявки (кто ведёт, обычный срок, место в очереди); глобальный поиск Ctrl+K только по своим данным; заметка к паре с IDOR-тестом; тёмная тема. Для каждой фичи — строка в README «идея подсмотрена у …», запись в decisions.md, постановка здесь, скриншоты 360 px.

Почему так: каждая фича привязана к найденному у аналогов приёму или пробелу (docs/research/02-competitors.md) и имеет оценку времени, а условие безопасности сформулировано вместе с фичей («кэш только для своего пользователя», «чужой токен → 404»). Агенту не нужно додумывать, где граница доступа.

### 2.1 PWA
Подзадача агенту: «офлайн для трёх страниц, кэш раздельный по пользователю и стирается при выходе; тест должен доказать, что после выхода без сети персональных данных нет». Что вышло: свой `sw.js` без библиотек, спека docs/specs/pwa.md, тест `06-pwa`. Тест прошёл с первого раза, поэтому агент проверил его на поломку: отключил очистку кэша — тест упал.

### 2.2 Календарь (.ics)
Подзадача: «личная ссылка-подписка, токен случайный, не id; перевыпуск делает старую недействительной; тест: старый или чужой токен → 404». Агент добавил своё решение: хранить только хеш токена. Что вышло: `src/lib/calendar/ics.ts` (RFC 5545 без библиотек, 4 юнит-теста), маршрут `/api/calendar/[token]`, экран `/schedule/calendar`, тест `07-calendar`.

### 2.3 Прозрачность заявки
Подзадача: «кто ведёт (роль и вымышленное имя), обычный срок по типу, место в очереди — поверх существующей очереди». Агент сделал место в очереди агрегатом (два числа) и считает его только после проверки владельца. Что вышло: колонка `assignee_name`, `typicalDays` в каталоге, `addBusinessDays` с тестами, карточка на странице заявки, тест `08-transparency`.

### 2.4 Поиск Ctrl+K
Подзадача: «по разделам, дисциплинам, своим заявкам и объявлениям; на мобильном иконка в шапке; только свои данные, проверка на сервере». Что вышло: `src/lib/search/match.ts` (4 юнит-теста), `searchAction`, `SearchDialog` (клавиатура, ARIA combobox), тест `09-search`, в том числе негативный: чужой номер заявки → «Ничего не нашли». После первого скриншота агент поменял порядок групп: свои заявки выше каталога.

### 2.5 Заметка к паре
Подзадача: «своя, видна только владельцу, IDOR-тест». Что вышло: таблица `lesson_note`, `LEFT JOIN` с автором в условии, `saveLessonNoteAction` с проверкой группы, тест `10-notes` с подменой `lessonId`. Первый прогон упал из-за «перескакивающего» локатора, это ошибка теста, а не кода. Затем тест проверили на поломку.

### 2.6 Тёмная тема
Подзадача: «если shadcn-токены позволяют без переделки». Агент сначала поискал места со сплошным `bg-warning` и текстом того же оттенка, которые в тёмной теме слились бы, и поправил три таких места. Что вышло: палитра `.dark`, `ThemeSwitcher` в профиле, тест `11-theme` (сохранение выбора, «как в системе», 360 px без прокрутки), тёмные скриншоты.

## Постановка 3. Правки по независимой проверке (17.11)

> Третий заход: правки по итогам независимой придирчивой проверки (жюри + технический аудит безопасности). Прочитай отчёты целиком. Скрипты атак аудитора перенеси в e2e/юнит-тесты как регрессионные (сначала тест падает, потом чинишь). Порядок: 1) закрыть эндпоинты Better Auth, через которые любой меняет пароль демо-аккаунта; 2) копии персонажей и кнопки «Войти как…»; 3) даты сида доживают до 28.11; 4) рейтинги однокурсников не уходят в браузер; 5) лимит входа по IP за прокси; 6) надёжность (БД при старте, health, sequence, гонки, валидация, CSP); 7) тексты и UX; 8) CLAUDE.md без шаблона, реально работающие хуки и агенты; 9) скриншоты на чистых данных; 10) «Вопрос в учебный офис» — если останется время.

Почему так: проверку делали отдельные агенты, которые не писали код (жюри по критериям и аудитор с атаками на прод-сборку), поэтому их находки не «подтверждали гипотезу автора». Постановка требует закреплять каждую находку тестом, который сначала падает, — так видно, что тест действительно ловит проблему.

Что вышло: 10 пунктов, каждый отдельным коммитом. Находки и как их закрыли — в `docs/decisions.md`, раздел «Независимая проверка». Для К1, В4, М2–М5 тест сначала упал, после правки проходит. Для гонки статусов, заметок и переписки тесты ещё и проверены на поломку. После правок агент `access-reviewer` из `.claude/agents/` прогнан по изменениям третьего захода.
